# External SMTP connection store — staging only

This unmounted store creates, lists, replaces and revokes account-owned SMTP settings. Name, email, host, port and security mode are stored as configuration; username and password are encrypted together with AES-GCM and account/connection-associated data. List output omits credentials and ciphertext. Every new or replaced record is unverified. Replacement requires the complete settings and credentials and uses revision compare-and-set. Revocation is soft so historical monitoring attribution can remain intact.

This does not implement authentication or an API, socket connections, verified sender status, sender selection, sending, credential key provisioning/rotation, retention, or a dashboard. It must not be exposed directly: the eventual route must obtain the account from the authenticated principal, validate origin, enforce authorization, and map errors without disclosing secrets. The send dispatcher must use an immutable connection revision to avoid changing the meaning of already queued messages. The key version must resolve through a managed keyring with tested rotation and recovery. Outbound DNS, private-IP and rebinding protections must be established before any connection test or delivery. SMTP passwords must never be returned or logged.

Migrations 0016 and 0017 are staged only; confirm ordering and compatibility before applying. No production data or Android source is changed; Android acceptance is required once the dashboard is connected. Local tests use synthetic SQLite and credentials; they do not prove Cloudflare D1 or SMTP behavior. The TSX dashboard, API wiring and all release gates remain outstanding.
