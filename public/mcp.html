01 / OVERVIEW

Tools for focused work.

Model Context Protocol (MCP) lets compatible assistants interact with defined tools. LeadMASTER includes an experimental, read-only MCP endpoint in the repository. It is disabled by default and is not available in the current public preview.

The current preview cannot authenticate users, send email or provide a live MCP service. Do not submit credentials or messages to the preview.
02 / CAPABILITIES

Clear boundaries.

The experimental integration defines two tools:

get_email_capabilities describes the MCP integration; it is not a live health check.

validate_email checks a message against queue input rules without storing, queueing or sending it. It does not verify recipients, consent, sender identity, quota or delivery.

Sending, delivery history, campaigns, audiences, templates, AI generation and account management are not available through MCP. This is not a complete Resend-compatible integration.

03 / SECURITY

Access by design.

The experimental endpoint requires a separate high-entropy bearer token and checks browser origins when supplied. The token is not an SES credential. It currently has no OAuth flow, per-client scopes or production rate limiting. Do not connect third-party assistants or deploy it publicly until its authorization and abuse controls have been reviewed.

Tool inputs can include personal data. Send only information an authorized operator has permission to process. The validation tool does not echo the message in its result.

04 / EMAIL DELIVERY

SMTP, not an AWS API.

The intended email transport is AWS SES SMTP, with credentials held in Cloudflare secret storage. The MCP tools do not use those credentials. The repository includes a queue and single dispatch coordinator under development; no production delivery guarantee is made.

Receiving delivery events may require a separately configured and verified webhook integration; no webhook delivery status is currently provided by MCP.

05 / RELEASE

Before connecting.

A production launch requires reviewed client authorization, token lifecycle and abuse controls; working authentication; safe queue acceptance and recovery; verified sender and SES quotas; observability; and end-to-end testing in a dedicated environment. No live connection instructions are offered until those requirements are met.
