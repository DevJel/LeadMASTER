01 / AVAILABILITY

Repository implementation only.

LeadMASTER contains an experimental Streamable HTTP MCP server in the repository. It is disabled by default and is not mounted by the current production Worker. There is no supported public MCP endpoint, production connection URL, client credential or OAuth registration. Do not attempt to connect an assistant to the production domain using /mcp.

MCP is read-only in this implementation. It cannot send, queue, retrieve or report email. It is not available as a live production integration.
02 / TOOLS

Two limited tools.

get_email_capabilities

Returns a static description of the experimental integration and its limited tool set. It is not a live health check and does not confirm that LeadMASTER services are available.

validate_email

Checks the shape and size of a proposed message against LeadMASTER queue input rules. It does not save, queue or send the message, verify the recipient, check consent or sender identity, inspect SES quotas, or confirm delivery. Message content is not echoed in the tool result.

There are no tools for sending, campaign management, audience management, templates, delivery history, analytics or account administration.

03 / PROTOCOL

Streamable HTTP design.

The source implementation uses the official MCP SDK's stateless Streamable HTTP transport and JSON responses. The handler accepts POST requests with JSON content and enforces a 100 KB request-body limit. Non-POST requests and unsupported content types are rejected.

When enabled in an isolated test deployment, the handler expects a bearer token and optionally checks an exact allowed Origin. These implementation details are not a production service contract because the route is not deployed or exposed by the current production Worker.

04 / AUTHENTICATION & SECURITY

Separate credentials, strict boundaries.

The experimental handler requires MCP_EXPERIMENTAL_ENABLED=true and a separate MCP_ACCESS_TOKEN secret. The token must be a cryptographically random base64url value of 43–128 characters (at least 32 random bytes). It must never reuse an administrator password, session secret, SES SMTP credential or email API key.

This prototype uses bearer-token authentication, not OAuth. It has no per-client scopes, client registration, token issuance or rotation service, or production rate-limiting layer. Any token holder can call every exposed tool. An Origin check is not a substitute for authorization or CORS. Do not expose this prototype publicly or connect third-party assistants before independent security review, client-level authorization, abuse controls, monitoring and privacy review.

05 / DEPLOYMENT REQUIREMENTS

Before a live connection.

Complete an isolated staging deployment, runtime compatibility tests, client authorization and token lifecycle, abuse/rate controls, request logging policy, monitoring and security review. Confirm that the MCP tool set remains read-only and cannot bypass the application's authentication or email-send controls. Any future send capability requires a separately reviewed API and durable queue/recovery design; it must not be added implicitly to MCP.

Local tests use mocked boundaries and do not establish production deployment, authorization safety or email delivery.
