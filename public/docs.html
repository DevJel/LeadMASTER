01 / OVERVIEW

A live gateway. A product still in development.

LeadMASTER's production Worker is hosted at https://leadmaster.jelvan.pro. It provides a single-administrator authentication gateway, Turnstile verification, email OTP, D1-backed sessions and security alerts sent through AWS SES SMTP. The dashboard currently provides administrator navigation and developer API-key management. The developer email API supports scoped transactional sending and signed email-outcome webhooks; campaigns, audiences, templates, attachments and advanced delivery analytics remain outside the current release.

Production authentication, the scoped developer email API and webhook management routes are deployed. Full SES delivery and callback integration still require controlled end-to-end verification.
02 / AUTHENTICATION API

Protected administrator access.

All endpoints are same-origin on https://leadmaster.jelvan.pro. Requests that change state require same-origin requests and JSON bodies. Do not call these endpoints from third-party origins.

GET /api/auth/config

Returns the public Turnstile site key required by the login interface. This is public configuration; the Turnstile secret is never returned.

POST /api/auth/login

Starts the administrator sign-in flow. JSON body: {"identity":"admin email","password":"…","turnstileToken":"…"}. The server checks the administrator allowlist, password, Turnstile action and rate limits, then sends a six-digit email verification code. Success returns {"next":"verify_email"}. The code expires after 10 minutes and is single-use.

POST /api/auth/verify

JSON body: {"code":"123456"}. A valid code creates an eight-hour session and returns {"authenticated":true} with a Secure, HttpOnly, SameSite=Strict session cookie. The challenge allows at most five attempts.

GET /api/auth/session and POST /api/auth/logout

The session endpoint reports whether the current browser session is authenticated. Logout revokes the D1-backed session and expires the session cookie. Do not store session tokens in local storage or expose them to scripts.

These are browser authentication endpoints, not general-purpose API credentials or an external user-management API. The current deployment has a single configured administrator.

03 / DEVELOPER EMAIL API

Connect your applications.

LeadMASTER is designed to let developers generate application-specific API credentials, store them securely in their own backend, and submit transactional email through the LeadMASTER HTTPS API. Use separate keys for each application and environment, with only the scopes required.

DEVELOPER INTEGRATIONPOST /api/v1/emails
Authorization: Bearer lm_live_…
Content-Type: application/json
Idempotency-Key: unique-request-id

The deployed API supports one recipient, subject, required plain-text body and optional HTML body, plus message request status, idempotency, scoped developer API keys and signed delivery webhooks. Attachments, CC/BCC, multiple recipients, custom sender identities and campaigns are not included in this API contract.

Release status: the updated Worker, developer API routes, D1 schema and Secrets Store bindings are deployed. Public route checks confirm that the API handlers are active. Authenticated SES sending and webhook callback signature verification still require controlled end-to-end tests; a successful route response is not proof of inbox delivery.

03 / DEVELOPER WEBHOOKS

Connect email events to your application.

Developers can create named webhook subscriptions using an API key with the webhook:manage scope. Register an HTTPS callback URL and choose the email events to receive: email.accepted, email.failed and email.unknown.

LeadMASTER signs each raw event body with HMAC-SHA256. Your server verifies the LeadMASTER-Timestamp and LeadMASTER-Signature headers using the one-time signing secret. Signing secrets are encrypted at rest. The webhook console can list subscriptions, revoke them and inspect the latest delivery attempts.

Current delivery behavior: one synchronous attempt per matching event, redirects disabled and a seven-second timeout. Automatic retries, replay, dead-letter recovery and SES bounce/complaint/open/click events are not yet available. Delivery events indicate SMTP submission outcomes, not inbox delivery.

04 / EMAIL TRANSPORT

SES SMTP for system email.

The deployed gateway uses AWS SES SMTP to send administrator sign-in codes, best-effort security alerts and scoped developer email API requests. SMTP host, username and password, sender configuration and other credentials are kept in Cloudflare Secrets Store bindings. The application uses implicit TLS on port 465.

SES acceptance is not proof of final inbox delivery. The production authentication flow depends on successful OTP email delivery; live deliverability, sender identity status and quota have not been independently confirmed here. General customer email sending, campaigns and delivery analytics are not available.

05 / SECURITY & RELEASE

Keep the boundaries clear.

Turnstile is verified server-side for the configured hostname and action. Password verification, rate limiting, one-time OTP challenges, session-token hashing, expiry and revocation are handled by the Worker and dedicated D1 database. Secrets are referenced through Cloudflare Secrets Store and are not returned to browsers or stored in the repository.

Before enabling the wider email product, complete independent security review, scoped API credentials, durable sending and reconciliation, queue and dead-letter monitoring, retention and deletion controls, consent and suppression workflows, SES sender/quota verification, and live end-to-end tests.
