01 / OVERVIEW

Email for your applications, from LeadMASTER.

LeadMASTER gives developers a simple HTTPS API for transactional email, request status lookups and signed webhooks. Base URL: https://leadmaster.jelvan.pro.

FeatureWhat it does
LeadMASTER Email APISend one transactional email per request with idempotency and rate limiting.
LeadMASTER Request statusLook up the status of any email submitted with your API key.
LeadMASTER API keysCreate scoped keys for sending, reading status or managing webhooks, and revoke them at any time.
LeadMASTER WebhooksReceive signed email events at your HTTPS endpoint and review recent attempts.
LeadMASTER HTML previewPreview email HTML safely in the dashboard.
Every feature on this page is provided by LeadMASTER. The LeadMASTER dashboard is available to the workspace administrator; campaigns, audiences and templates are not available yet.
02 / API KEYS

Create a LeadMASTER API key.

  1. Sign in to the LeadMASTER dashboard and open API Keys. Keys are issued by the workspace administrator.
  2. Enter an application name and choose a scope.
  3. Select Generate key and copy it immediately. LeadMASTER shows it only once.
  4. Store it as a server-side environment variable such as LEADMASTER_API_KEY.
  5. Select Revoke for any key that is retired or exposed.
ScopeAllows
email:sendSubmit email
email:readRead the status of requests made with the same key
webhook:manageCreate, list and revoke webhooks and read delivery logs

Keys begin with lm_live_. Never put a key in browser code, a mobile app or a public repository.

03 / SEND EMAIL

Send an email with LeadMASTER.

POST /api/v1/emails with the headers Authorization: Bearer <key>, Content-Type: application/json and Idempotency-Key (16–128 characters). Only to, subject, text and optional html are accepted. LeadMASTER sets the sender.

REQUEST BODY{ "to": "recipient@example.com", "subject": "Your order confirmation", "text": "Thanks for your order.", "html": "<h1>Thank you</h1><p>Your order is being processed.</p>" }
CURLcurl -X POST "https://leadmaster.jelvan.pro/api/v1/emails" \ -H "Authorization: Bearer $LEADMASTER_API_KEY" \ -H "Content-Type: application/json" \ -H "Idempotency-Key: order-184-confirmation" \ --data '{"to":"recipient@example.com","subject":"Order confirmation","text":"Your order has been received."}'
NODE.JSconst response = await fetch("https://leadmaster.jelvan.pro/api/v1/emails", { method: "POST", headers: { Authorization: `Bearer ${process.env.LEADMASTER_API_KEY}`, "Content-Type": "application/json", "Idempotency-Key": "order-184-confirmation" }, body: JSON.stringify({ to: "recipient@example.com", subject: "Order confirmation", text: "Your order has been received." }) }); const result = await response.json(); if (!response.ok && response.status !== 202) throw new Error(result.error || "LeadMASTER request failed");
PYTHONimport os, requests r = requests.post( "https://leadmaster.jelvan.pro/api/v1/emails", headers={ "Authorization": f"Bearer {os.environ['LEADMASTER_API_KEY']}", "Content-Type": "application/json", "Idempotency-Key": "order-184-confirmation", }, json={"to": "recipient@example.com", "subject": "Order confirmation", "text": "Your order has been received."}, timeout=20, ) print(r.status_code, r.json())
RESPONSE 200{ "id": "0b7f6c0e-…", "status": "accepted", "message": "LeadMASTER accepted the message for processing. This is not proof of inbox delivery." }

Idempotency

Repeat a request with the same Idempotency-Key to get the original result with "replayed": true and no second message. A request with status failed is replayed too, so use a new key to try again after a failure. For unknown, check the request status before sending again.

04 / REQUEST STATUS

Check what happened.

GET /api/v1/emails/{id} requires email:read and returns only requests created with the same key. Timestamps are Unix milliseconds.

RESPONSE{ "id": "0b7f6c0e-…", "status": "accepted", "recipient": "recipient@example.com", "subject": "Order confirmation", "created_at": 1767916800000, "updated_at": 1767916800412, "error_code": null }
StatusMeaning
sendingLeadMASTER has recorded the request and is processing it.
acceptedLeadMASTER accepted the message for processing. This is not proof of inbox delivery.
failedLeadMASTER could not submit the message. It was not sent.
unknownThe result could not be confirmed. The message may have been sent. Do not resend automatically.
05 / WEBHOOKS

LeadMASTER webhooks.

Create a subscription with a key that has webhook:manage. Events: email.accepted, email.failed and email.unknown, sent for emails submitted with the key that created the webhook.

CREATEcurl -X POST "https://leadmaster.jelvan.pro/api/v1/webhooks" \ -H "Authorization: Bearer $LEADMASTER_API_KEY" \ -H "Content-Type: application/json" \ --data '{"name":"Storefront email events","url":"https://api.example.com/hooks/leadmaster","events":["email.accepted","email.failed","email.unknown"]}'
RESPONSE 201{ "id": "5d1c…", "name": "Storefront email events", "url": "https://api.example.com/hooks/leadmaster", "events": ["email.accepted", "email.failed", "email.unknown"], "signing_secret": "whsec_…", "created_at": 1767916800000, "warning": "Copy the signing secret now. It is shown only once." }

The signing_secret is shown once. The URL must be public HTTPS on port 443, without credentials; IP addresses and local or internal hostnames are rejected. This is basic hostname validation, not DNS pinning; only register callback hosts you control and ensure they cannot resolve or rebind to private network addresses.

EVENT PAYLOAD{ "id": "event-uuid", "type": "email.accepted", "created_at": "2026-11-09T00:00:00.000Z", "data": { "request_id": "email-request-uuid", "recipient": "recipient@example.com", "subject": "Order confirmation" } }

Verify the signature

Each request carries LeadMASTER-Id, LeadMASTER-Timestamp (Unix seconds) and LeadMASTER-Signature (v1=<hex>). The signature is HMAC-SHA256 of timestamp + "." + rawBody with your signing secret. Compare in constant time, reject timestamps older than five minutes and ignore event IDs you have already handled.

NODE.JSimport crypto from "node:crypto"; // rawBody must be the exact request body string, read before JSON parsing. export function verifyLeadMasterWebhook(headers, rawBody, secret) { const timestamp = String(headers["leadmaster-timestamp"] || ""); const received = String(headers["leadmaster-signature"] || ""); if (!/^\d+$/.test(timestamp)) return false; if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false; const expected = "v1=" + crypto.createHmac("sha256", secret) .update(timestamp + "." + rawBody).digest("hex"); const a = Buffer.from(received), b = Buffer.from(expected); return a.length === b.length && crypto.timingSafeEqual(a, b); }
PYTHONimport hmac, hashlib, time def verify_leadmaster_webhook(headers, raw_body: bytes, secret: str) -> bool: ts = headers.get("leadmaster-timestamp", "") received = headers.get("leadmaster-signature", "") if not ts.isdigit() or abs(time.time() - int(ts)) > 300: return False signed = ts.encode() + b"." + raw_body expected = "v1=" + hmac.new(secret.encode(), signed, hashlib.sha256).hexdigest() return hmac.compare_digest(received, expected)

Manage webhooks

  • GET /api/v1/webhooks lists your subscriptions.
  • DELETE /api/v1/webhooks/{id} revokes one.
  • GET /api/v1/webhooks/{id}/deliveries returns the latest 50 attempts.
DELIVERIES{ "deliveries": [ { "id": "…", "event_type": "email.accepted", "event_id": "…", "http_status": 200, "attempted_at": 1767916800500, "success": 1 } ] }

Delivery behavior: one attempt per event, a 7-second timeout, no redirects. Any 2xx response is a success. Automatic retries and replay are not available yet, so reconcile with the request status endpoint when needed.

07 / ERRORS

Errors.

Errors return JSON such as {"error":"…"}.

HTTPMeaning
202The outcome of an email submission is unknown (status unknown). Check the request status before resending.
400Invalid JSON, invalid fields, missing or malformed Idempotency-Key, or an invalid webhook URL or event list.
401Missing, invalid or revoked LeadMASTER API key.
403The API key does not have the required scope.
404The email request or webhook was not found for this API key.
405Method not allowed for this endpoint.
409The request could not be recorded. Retry with the same Idempotency-Key.
415Content-Type must be application/json.
429Rate limit exceeded. Wait for the number of seconds in Retry-After.
502LeadMASTER could not submit the message (status failed). Use a new Idempotency-Key to try again.
503The LeadMASTER service is temporarily unavailable.
08 / BEST PRACTICES

Build it safely.

  • Keep keys and signing secrets on your server and redact Authorization and signature headers in logs.
  • Use one key per application and environment with the fewest scopes needed.
  • Rotate by creating and deploying the new key before revoking the old one.
  • Honor consent and unsubscribe rules in your application before you send.
  • accepted means LeadMASTER accepted the message for processing, not that it reached an inbox.
